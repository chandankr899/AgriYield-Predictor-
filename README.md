
# AgriYield Predictor — Full-Stack Major Project

A runnable crop-yield prediction prototype based on the AgriYield project brief. Built with Python, Flask, scikit-learn, SQLite, HTML, CSS and JavaScript.

## Features
- Responsive dashboard and yield prediction form
- Flask REST API: health, metrics, feature importance, prediction, history and batch CSV
- Random Forest regression pipeline with OneHotEncoder
- MAE, RMSE and R² evaluation on a held-out test split
- Feature importance chart
- SQLite prediction history
- CSV batch prediction and downloadable results
- Input validation and automated model tests

## Dataset honesty — important for interviews
The app trains on **synthetic demonstration data** generated by `model.py` so it runs immediately and reproducibly. Dashboard metrics apply only to a synthetic held-out split; they are not real-world agricultural accuracy. Do not claim that they validate farming decisions. For a research-grade release, source actual yield (e.g. tonnes/hectare) aligned with crop, region, season, weather and soil observations. The crop-recommendation dataset mentioned in the initial brief is not itself a measured crop-yield dataset. Document dataset source, licence, units, date range, cleaning and validation strategy.

## Run on Windows
1. Install Python 3.10+.
2. Extract this ZIP and open the folder in VS Code.
3. In Terminal:

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python app.py
```

4. Visit **http://127.0.0.1:5000** in Chrome. First launch trains and saves the model. SQLite database is created automatically.

Run tests: `pytest -q`

## API
| Method | Route | Purpose |
|---|---|---|
| GET | `/api/health` | Service health |
| GET | `/api/metrics` | Test metrics |
| GET | `/api/features` | Feature importance |
| GET | `/api/history` | Latest saved predictions |
| POST | `/api/predict` | JSON prediction |
| POST | `/api/batch` | CSV upload; returns enriched CSV in JSON |
Prediction JSON keys: `crop`, `soil_type`, `rainfall`, `temperature`, `humidity`, `nitrogen`, `phosphorus`, `potassium`, `ph`, `area_hectares`. Download sample at `/static/sample_input.csv`.

## Architecture
Browser form/CSV upload → Flask routes → validation → scikit-learn preprocessing pipeline (OneHotEncoder + numeric features) → RandomForestRegressor → JSON result → SQLite history. Batch endpoint uses pandas to process CSV rows.

## Interview explanation
**Problem:** Estimate yield from crop, soil and environmental parameters. **Frontend:** responsive HTML/CSS/JS, forms, charts and async fetch calls. **Backend:** Flask REST endpoints, validation and error handling. **ML:** OneHotEncoder + RandomForestRegressor; evaluate with MAE, RMSE and R²; feature importance for interpretation. **Database:** SQLite stores input values, outputs and timestamps. **Batch:** pandas reads CSV and appends predicted yield columns.

The displayed tree-spread range is a model variation estimate, not a calibrated confidence interval. Production improvements: real datasets, temporal/region-based validation, SHAP, calibrated intervals, authentication, model versioning, drift monitoring and deployment hardening.
